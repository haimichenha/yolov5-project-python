# YOLOv5 识别快捷包使用说明

这是一个由教学提供文件继续修改而来的 YOLOv5 训练快捷包。它属于一次初步训练成果：通过多个 Python 脚本，把图片、Labelme 标注 JSON、YOLO TXT 标签及训练/验证集的整理过程串联起来，以减少手工搬运文件的步骤。

> 该包不是经过系统调参的完整工程，而是在半成品包基础上继续修改的便捷使用包。原始记录只说明识别精度一般，未保留可复核的 Precision、Recall 或 mAP 数值。

## 获取完整使用包

完整文件位于 `team.rar`，通过 Git LFS 管理。克隆仓库后先执行：

```bash
git lfs pull
```

下载完成后再解压使用。图片的批量命名可用其他常规工具完成。

## 原始使用边界

- `dataset.py` 与 `train.py` 不建议在不了解训练流程时大幅修改。原始说明记录：`dataset.py` 通常只运行第一个入口；`train.py` 仅在约第 494 行做过小改。
- 该包的脚本和目录名沿用原始命名，包括 `boat.py`、`imageManger.py`、`latroYun.py`、`fanlabel.py`、`tryDetect.py`、`txtrds`、`txtManager` 与 `zhunbei`；使用时不要随意改名。
- 原始脚本曾使用本机绝对路径。复现时应把它们改为当前解压目录下对应的 `dataset/train/labels` 和 `dataset/val/labels` 路径，而不是直接沿用旧路径。

## 完整数据集制作流程

### 1. 图片、JSON 与备份

1. `dataset` 文件夹中的 `train` 是训练图片存放位置，先将待训练图片放入其中。
2. 使用 Labelme 框选目标并保存 JSON。JSON 默认会和图片保存在一起；完成标注后，将这些 JSON 移动到 `json` 文件夹。
3. 备份材料可放入 `zhunbei` 文件夹，再开始后续转换。

### 2. JSON 转为 YOLO TXT

运行 `boat.py`，将 JSON 标注转换为 YOLO 所需的 TXT 文件。转换后的文本会放在 `txtrds` 文件夹中。

图片数量、标签数量与文件名必须对应：一张训练/验证图片应有同名 TXT 标签。若名称或数量不一致，先修正对应关系再进行划分与复制。

### 3. 划分训练集与验证集

运行 `imageManger.py`。该脚本只会按比例将训练集 `train` 中的图片随机复制到验证集 `val`，不会替代标签整理。因此训练集和验证集的标签目录中都需要有与图片同名的 TXT 文件：

```text
dataset/train/labels
dataset/val/labels
```

### 4. 分发标签并生成 YAML

运行 `latroYun.py`。按原始说明，脚本会将 TXT 文件先复制到 `dataset/txtManager` 中转目录（该目录应保留；部分情况下不经中转也可继续），再结合 `txtrds`、`train/images` 与 `val/images` 的内容，将文本复制到对应的 `labels` 文件夹。

无法匹配的图片或文本会被移入名称明确的单独目录。原始使用记录中这些目录未导致错误，但仍应逐项检查，避免将遗漏标签带入训练。脚本还会生成对应 YAML，必须检查其中的数据集路径和 `nc`（类别数）。

### 5. 补齐标签目录

`fanlabel.py` 会为各文本文件夹生成 `labels`。原始记录未确认 `dataset` 根目录是否必须额外保留 `labels`，因此以本次脚本生成的 YAML 和训练实际读取路径为准。

## 训练、检测与导出

1. 在 `train.py` 中使用权重时，必须配套使用相应的 YAML，并将其中的 `nc` 改为正确的类别数；它应与脚本生成的 `screentrain.yaml` 保持一致。
2. 原始记录仅尝试过 `v5lite-c.pt`，并在 **450 epochs 以上** 完成过训练。训练轮数是一次训练任务内的设置，不是反复启动 `train.py` 的次数。
3. 若要改善识别效果，原始经验是补充更多目标框，并尽量让标注框贴合目标。该经验不构成具体精度指标承诺。
4. `tryDetect.py` 用于检验训练权重效果；运行前需要将权重路径改到 `runs` 下的实际输出位置。
5. `pipi` 文件夹用于导出给树莓派使用的文件。
6. 原始 `train.py` 配置使用 GPU `"0"`，可按本机 GPU 环境修改。
